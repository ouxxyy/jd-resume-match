# 内容表达标准（jd-match-voice/0.2.0）

> 定位：`scoring-rubric.md` 决定**怎么判**，本文件决定**怎么说**。它不改任何分数、状态与建议——判定一律以评分契约与脚本复算为准，表达只负责把既定结论说成人话。与评分契约冲突时，评分契约优先。

## 0. 适用范围

报告 JSON 中所有由模型撰写、用户会读到的文字，按本标准产出：

| 文案面 | 字段 |
|---|---|
| 首屏结论 | `jobs[].suggestion_rationale`、`jobs[].rank_rationale` |
| 关键发现 | `share_payload.headline_findings`、`gate_notes`、`disclaimer` |
| 逐条判定 | `requirements[].rationale`、`gates[].rationale` |
| 改写 | `rewrites[].rewritten_text`、`rationale`、`ask` |
| 行动 | `actions[].goal`、`deliverable`、`completion_criteria` |
| 交付口径 | SKILL.md 第 6 步给用户的三句话结论 |

后续内容编排 JSON（报告导语、卡片文案、发布标题与正文）同样按本标准执行；其数据结构由工程步骤另行定义，本文件只管文字。

## 1. 三条底线

1. **先回答问题，再给分数。** 用户带着三个问题来：这个岗位怎么投？为什么？先改哪处？首屏文案按此顺序回答；分数是辅助信息，跟在结论后面，不替代结论。
2. **句句有锚点。** 每句判断必须能指到一段具体经历、一条 JD 要求或一句简历原文。指不出锚点的话，删掉。
3. **锋芒对写法，不对人。** 可以说「这句话把 4600 埋进了句尾」，不可以说「你不会包装自己」。批评对象永远是句子和结构，不是能力与人格；不编造任何招聘结果。

## 2. 语言规则：内部话不出机房

用户可见正文（含展开详情里的判定理由）禁止出现：

- **一切机器标识**：`gate-a1-g2`、`req-a1-r1`、`ev-a2`、`job-a1` 之类 ID。指代门槛就说「大促周末值班这条一票条件」，指代岗位用岗位名。
- **状态机词**：met / unmet / partial / supported / unknown / pending_confirmation 不得出现在中文句子里。用人话：核实通过 / 明确不满足 / 只做了一半 / 有实据 / 看不出来 / 待确认。
- **规则引用**：§1、决策表第 N 条、rubric、schema、R14、`docs/…` 路径。规则依据留给内部审计文档；对用户只给事实对照与结论。
- **算式**：「75≥70 且未知项 ≤ 1/3」。要说条件就说人话条件（「值班这条核实通过后，这份简历就够得上『优先投』档」）。

**定位放详情，不进正文**：证据出处在展开详情的定位行给人话版本（「简历 · 实习经历第 1 条」），不把 `src-resume-1 L8` 之类定位符嵌进句子。

**空话黑名单**（出现即重写）：提升竞争力、突出优势、强化亮点、展现自我、增加砝码、「进一步优化表述以提升匹配度」以及一切正确的废话。点评必须落到具体经历、岗位要求或简历句子。

## 3. 各文案面写法

### 3.1 首屏结论（suggestion_rationale）

回答三问，顺序固定：怎么投 → 为什么 → 先改哪处。两到四句。分数最多出现一次，且永远跟着一句口径说明（分数衡量证据覆盖，不是录取概率）。

### 3.2 排序理由（rank_rationale）

用人话比较：岗位名 + 各自强弱 + 主目标为什么选它。不出现岗位 ID，不重复免责声明（渲染层已有）。

### 3.3 关键发现（headline_findings）

现契约为单一列表，同时上报告首屏与分享卡；样稿按两个用途的交集写：**具体到有锚点**（报告面要求），**值得陌生人收藏**（传播面要求）。优先写三类素材：被埋没的强证据、被高估的弱表述、一句话能补的缺口。有数字用数字。

匿名纪律（分享面恒成立）：无人名、校名、公司名、城市；数字保留反差所需的精度，但不得组合多条形成可识别画像。发布素材基于合成案例时，正文须注明合成案例。

### 3.4 判定理由（requirements / gates 的 rationale）

公式：**JD 要什么 → 简历有什么/没什么 → 所以记成什么**，三句以内。规则条款、审计编号一律不出现；材料矛盾与强度备注保留（那是有用信息），用直白的话说。「没写清楚」永远保持「没写清」的定性，不得写成「不会」「缺乏能力」。

### 3.5 改写（rewrites）

改写文本过**事实保真清单**（违反任何一条就重写）：

1. 数字逐个对：新句每个数字在原句或同一经历条目里有原样出处；
2. 职责范围词零新增：独立 / 主导 / 负责 / 带领 / 统筹，原句没有就不准出现；
3. 归属不变：团队的数字不能变成「我」的，集体成果不能变成个人成果；
4. 不跨经历拼接：实习的数字不与校园经历合并成一句；
5. 只动结构不动事实：语序、主干、括号降级可以；事件、因果、规模不可以。

改写理由按**批注风**：先引 JD 关键词，再指出原句的具体毛病（埋数字、动词弱、缺频次），最后说改法。这条改写救不了的部分（真缺口）要明说，并指路补什么、去哪补。

### 3.6 行动清单（actions）

- `goal`：动词开头的具体动作 + 对象 + 场景，不挂任何编号。「核实大促周末值班安排（gate-a1-g2）」→「给 HR 发一句话，问清大促周末值班频率」。
- `deliverable`：交出什么（一句话话术、一版简历、一条可引用经历），让用户知道做完长什么样。
- `completion_criteria`：可自检的人话标准。「可将门槛更新为 met 或 unmet」→「拿到 HR 明确答复，决定投或不投」。
- 排序按「先做便宜的」：几分钟能完成的事实核查在前，要动手写的在后。

### 3.7 分享与发布文案（标题 + 正文）

标题三选一交付，每条必须能指向报告里的一条具体证据（发现、改写或门槛）。

允许的锋利：数字反差（「JD 要 3000+，简历里躺着 4600」）、写法批评（「硬数字在括号里」）、可收藏方法（「投前先问 HR 这一句话」）。

禁止的偷换：

- 没写清楚 ≠ 不会、缺乏能力；
- 表达改好 ≠ 录取率 / 通过率 / 面试概率提高——分数只随新增事实变化，润色不提分，更不预示任何招聘结果；
- 不得制造简历里不存在的情节（逆袭、翻盘、大厂）。

正文结构：钩子一句（来自最反差的发现）→ 三个发现（各一两句，带数字）→ 方法收束一句（可复制动作）→ 免责一句。默认无人设署名、无「评论领取」话术、不承诺任何结果。

### 3.8 成员版分享卡（editorial.member_card，0.2.0 新增）

成员版默认只出 1 张：岗位方向、匹配结论、优势与缺口、下一步方向，一屏读完。

- **优势与缺口并陈**：2–3 条 findings，至少一条 `advantage`（有证据的优势）与一条 `focus`（待补缺口）；只写优势或只写缺口都算失败。
- **低分不羞辱，高分不夸大**：缺口条写「缺什么证据、怎么补」，不写能力否定；优势条必须落到具体数字或事实，不得无出处拔高。
- **结论与门槛注记**：建议语（优先投 / 改好再投 / 先暂缓）与硬门槛状态由渲染器从报告读取，编排不得另写一套结论；`verdict_note` 仅在需要补充口径时使用，不得与报告判定矛盾。
- **下一步方向**：一条低成本可启动的动作（参照 3.6 行动写法），不承诺结果。
- 分数口径随卡附身：渲染器固定输出「分数只衡量简历证据对岗位的覆盖度」免责，编排文案里不重复、不改写。

### 3.9 交付三句话（SKILL.md 第 6 步）

固定三句：怎么投（含第一步动作）；最值钱也最委屈的发现（带数字）；现在就能做的第一步（5 分钟内可启动）。

## 4. 交付前自查

1. 全文检索：无 `gate-` / `req-` / `ev-` / `ans-` / `rw-` / `act-` / `job-`；无 met / unmet / partial 等英文状态词；无 §、决策表第 N 条、rubric、R14。
2. 首屏三问有答案，且分数不是第一句。
3. 每条发现能指到一条证据 / 改写 / 门槛；无锚点的句子已删。
4. 无空话黑名单词汇。
5. 改写句通过事实保真清单全部五条。
6. 无「独立 / 主导 / 负责」类新增词。
7. 无任何概率承诺（录取率、通过率、面试概率）。
8. 所有「没写清楚」保持原定性，未被偷换成「不会」。
9. 分享与发布文案匿名合格：无人名、校名、公司名、城市；合成案例已标注。
10. 状态与分数全部来自脚本复算，文案未引入任何新判定。
11. 成员卡优势与缺口并陈；无能力否定，无无出处拔高。
12. 真实案例进入报告可见原文时，公司、学校、独特项目及可识别数字组合已按编排 `redactions` 白名单泛化（不能只删姓名电话），渲染器复查通过。

## 版本政策

- 本文件是表达契约，不是评分契约；改动不影响分数与黄金案例期望值。
- 规则新增或修改升次版本号（0.1.x）并记变更；重大转向升主版本。

- 0.1.0（2026-09-12，MYW-69 计划第 2 步）：初版。
- 0.2.0（2026-09-15，MYW-72/MYW-73 T2）：新增 §3.8 成员版分享卡写法（优势与缺口并陈、低分不羞辱不夸大）；自查清单补成员卡与渲染级脱敏白名单两条；其余规则零改动。
